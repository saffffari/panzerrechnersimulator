## 2. What changed this session (all editor-independent, pending compile)

All pure-C++/ini; compile via Live Coding after reconnect. No `.uasset` was touched.

**Projectile = glowing tracer fireball** — `KesselProjectile.h/.cpp`
- New `Body` `UStaticMeshComponent` (engine Sphere, scaled `(3.5,1.4,1.4)` → ~175uu streak) is now the
  root; **collision disabled** (travel is line-trace; a colliding mesh would self-detonate at the muzzle).
- `BeginPlay` builds a bloom-hot emissive `UMaterialInstanceDynamic` (orange-white) on the body.
- `Tracer` point light re-parented under `Body`, brightened 2500→**12000**, radius 400→**900**.
- `Tick` drops a `SpawnTracerPuff` every `TrailInterval` (0.012s) → faked glowing tracer ribbon.

**Molten-metal impact** — `KesselProjectile.cpp::OnProjectileImpact`
- On penetration: white-hot core flash + warm halo + `SpawnGlowingSparks` (emissive physics ejecta)
  + spall debris + `SpawnLingeringHotPoint` (cooling-metal glow). Deflect path: lighter glowing sparks.

**Big main-gun muzzle blast** — `KesselGunComponent.cpp::Fire`
- Two layered bright flashes (40000/22000) + forward smoke/grit at the muzzle so firing is unmistakable.

**New FX primitives** — `KesselFXLibrary.h/.cpp`
- `SpawnTracerPuff`, `SpawnGlowingSparks` (hot emissive MID spheres), `SpawnLingeringHotPoint`;
  refactored the shared point-light spawn (also fixes the old mobility-after-register warning).

**Tank standstill** — `KesselTankPawn.cpp`
- `BeginPlay`: high ground-trace **seats the pawn on the surface** (lifts it out of the buried spawn).
- `Tick`: forward move only hard-stops on a **true wall** (`MoveHit.Normal.Z < 0.4`), not on slopes/bumps.

**Enemies flying into space** — `KesselGameMode.cpp/.h`
- `SpawnTestEnemies`: authoritative high trace; **only commit once every point hits terrain** (else
  re-defer up to 10×); spawn with `AlwaysSpawn` (no upward ejection). Added `EnemySpawnRetries`.

**PS1 crunch (code/ini half)** — `KesselAtmosphereController.h/.cpp`, `Config/DefaultEngine.ini`
- `ApplyRetroCVars()` (called from `BeginPlay`) drives a `MasterRetro` (default 0.6) dial: low internal
  res (480×270), `AAM_None`, nearest-neighbour upscale, flattened motion-blur/DoF/sharpen.
- `DefaultEngine.ini` floor sets the same so a fresh checkout / packaged build looks right pre-`BeginPlay`.

## 4. Other audit findings (not blocking first-playable; triage later)

**Combat**
- Projectile traces on `ECC_Visibility`, not the documented `WeaponTrace` channel — works against the
  enemy (blocks all) but foliage/Visibility cosmetics can eat rounds. (KesselProjectile.cpp:83)
- Per-substep drag math uses `SubDt*100` (seconds), not distance — frame-rate-dependent, near-zero drag.
  Should be `(Pos-PrevPos).Size()/100` to match `v(r)=v0·exp(-k·r)`. (KesselProjectile.cpp:76)
- `SpawnCounter` static never resets per-PIE despite the header comment → flank bearings drift to the
  250° clamp across editor sessions. (KesselEnemyTank.cpp:102)
- Ballistics `SpallScale` fallback 2.5 vs `UBallisticsConfig` default 1.0 → 2.5× lethality swing
  depending on whether a config asset is assigned. (KesselBallisticsSubsystem.cpp:59)
- Armor face validation + per-run RNG are TODO stubs (deterministic ricochet/spall).

**Support**
- IMC ownership is inverted vs. the architecture comments: the **pawn** owns/adds the mapping context;
  `AKesselPlayerController`'s "single owner of the IMC" claim + `DefaultMappingContext` are dead. Works,
  but per-view IMC swapping can't function until reconciled.
- HUD reticle never turns red: `ApplyKesselWinterMood` sets `SunIntensity=2.4` but `HUD::IsNight()`
  thresholds `<2.0` → the blizzard reads as "day," reticle stays near-black. Make the two agree.
- `UKesselAudioComponent::SetButtonedState` has zero callers — interior/exterior acoustics never switch.
- Atmosphere applies mood/snow synchronously in `BeginPlay` (no WP-streaming defer like the enemies),
  and `GetPlayerPawn` may be null then → snow can silently fail to spawn.
- `GunnerEye` scene component is dead (CamGunner attaches to GunMount).

**Docs reconciliation**
- The placeholder cube hull is **on-spec for M1** (MILESTONE_1_PLAN §2/§3 — static-mesh proxies until
  the real model lands); it's only a "bug" relative to the finished game. Real tracked/physics movement
  (`UKesselTrackedMovementComponent`) and audio are documented-but-unbuilt seams.
- `OVERNIGHT_BUILD_REPORT.md` control table is stale (says mouse-aim/LMB) vs LOCKED `CONTROLS.md`
  (arrows/Space/Shift) — the live pawn follows CONTROLS.md.

**Build/config:** the dedicated build/config audit agent returned a failed stub; the level-logs agent
covered the critical config facts (GlobalDefaultGameMode=`/Script/Kessel.KesselGameMode`, startup map
`/Game/L_KesselTest`). A focused Build.cs/Target.cs dependency pass is still worth doing.

## 5. Tuning notes
- **Projectile speed unchanged** (773–930 m/s → 77k–93k uu/s). Lowering it would break the ballistics
  (pen keys off range/velocity). Visibility comes from the bright fireball + tracer light + trail, which
  read as a fast streak. If a *slower, more trackable* round is wanted, decouple a cosmetic
  `VisualSpeedScale` from the ballistic trace (larger change — flagged, not done).
- `MasterRetro` (AtmosphereController) and `r.ScreenPercentage` (ini) are the PS1 intensity dials;
  480×270 (0.6) is a recognizable PS1 res — drop toward 320×180 (0.85+) or up to 960×540 (~0.2) to taste.
- The hot emissive look relies on **bloom** (kept on) to make >1 colors glow; verify the post-process
  volume / camera bloom under the locked exposure.
