# Runtime sound coverage — 5 September 2026

This is a source-routing and local asset audit, not an audition or an acoustic-accuracy certification. The new bank contains **eight verified source recordings**, but many active gameplay sounds remain generated. Review must use first-person videos with audio. No audio-only comparison, Cargo job or GPU job was run for this audit.

Evidence: [asset inventory and SHA-256 receipt](../artifacts/astra-audit-20260905/audio-runtime-coverage-20260905.json), [new bank recipes](../catalog/audio_feedback_20260905.json), [older optional layers](../catalog/pizza_audio_selection.v1.json), [feedback routing](../src/audio_feedback.rs), [sound bank and propagation](../src/audio.rs), [computed impact voices](../src/acoustics.rs). The receipt records the inspected source hashes; later edits/builds require their own receipts.

The documented game-owned extracted source has **914 audio files**: Rust & Blood 255, Echoes 471, ROT 188. Every selected new bank file matches its original bytes and manifest hash. Originals are unchanged. The local purchase designation is retained from the existing catalog; these checks do not establish a new license or permission to distribute standalone pack files.

## Current routing and remaining layers

- A successful new replacement returns immediately in `Audio::play`, `play_at_volume` and `play_world_muffled`. Those calls do **not** also play the former procedural base or optional v1 layer. World playback still applies direction, obstruction, reverb and closed-hull filtering to the replacement.
- Infantry `RifleShot`, `LugerShot`, repair `HammerStrike`, and both perspectives of the player main-gun report use the new bank. `hatch_move`, `hatch_stop` and `trigger` are dedicated control recordings. All are provisional adaptations; generic explosion clips are not recordings of a Tiger cannon.
- **Tank MG regression fixed in source:** `TankMgShot` now retains the exact former `ProceduralSound::RifleShot` voice and optional v1 layer pool, gains and variation seed. Both enemy tank MG dispatches migrated; infantry still receives the new rifle recording. Two `audio::tests::tank_mg_*` tests compare exact samples, propagated samples, replacement exclusion and legacy routing. Tests are added, not run by this audit; root owns the build gate. The already frozen v10 executable predates this fix.
- **Separate outstanding duplicate:** live `Game::enemy_fire` schedules a caliber-based `synth_gun_report` and also a generic `EnemyGun` when the muzzle is within 120 m. The custom buffer bypasses new replacements. This pre-existing extra report remains unchanged; it should be assessed independently of incoming armor-impact audio.
- Main-gun discharge still adds generated `MainGunRecoil` to the new recorded report. Loader mechanics use `play_mechanical` directly and therefore bypass generic `BreechClack`/`BrassClatter` replacements. These are separate physical cues, but have not yet been replaced with pack foley.
- Hatch motion owns one sink per moving lid, with a hard stop at arrival. `interact_hatch_lever` additionally plays generated `BreechClack` at 0.5 volume; the lever-only contact should be assessed in the same video as lid motion. Trigger recording precedes ready/unready discharge checks. No separate primer-misfire simulation is established by that trigger cue.
- Live penetration uses `synth_damage_impact_body` plus actual fragment-contact sounds; it deliberately omits the separately authored fragment shower. Body thuds within that computed event are casualty-count/timing approximations, not measured ragdoll-to-floor contacts. Generic hit/replay paths still have `ImpactTank`/`PenetrationHit` identities; replacing the player gun report does not replace them.
- The new bank defaults on locally unless `KESSEL_ENABLE_PIZZA_AUDIO=0`; v1 layers still require a truthy opt-in. The old startup message could therefore say “procedural-only” while eight new recordings subsequently loaded. This is corrected in the later source-only [bank reporting pass](AUDIO_BANK_REPORTING_20260905.md), including capture provenance and top-of-file documentation; the frozen v10.1 binary predates that reporting change.
- Additional closure issue found during that reporting pass: the optional v1 receipt expects 12 files, while its root now also contains the nine files in `feedback_20260905` (21 actual). The old guard rejects the older bank when opted in. A subsequent source pass recognizes only the independently verified feedback partition; see [partition fix receipt](../artifacts/astra-audit-20260905/audio-partition-verification-20260905.json). The offline validator passes all 20 tests and validates the actual bank; Rust tests await the next build. Frozen v10.2 still predates this fix.

Additional coverage gaps: no distinct gameplay event bindings were located for surface footsteps, clothing/breathing, paper/map handling, foam spray, fuel pouring, radio static or spoken crew/radio lines in the inspected gameplay/audio code. R includes metal/snow/wood/grass/dirt/gravel/concrete footsteps; O has `Machines/radio_static_mx_1_loop.ogg`; E/R have equip/lever/body contacts. No specific foam/fuel/breathing match was identified. Music exists in the packs, but the inspected runtime has no regular soundtrack binding. `synth_mg_gravel` is demo/test tooling, not the active tank MG source.

The next videos need to assess the player’s remaining complaints directly: gunfire character, weight/ringing versus noisy transients, louder but short hatch motion, trigger/failed-discharge feedback, starter behavior, traverse jam, and complete event-bound mechanical foley. Keep the approved engine, interior ambience, 45 mm impact and KV-2 MG as comparison anchors. Source-byte validation and finite sample tests cannot establish whether any replacement sounds good.
